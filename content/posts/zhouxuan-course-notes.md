## 合并之前先变基，再提交合并申请。如何理解这句话？

**先变基（rebase）**：把你的代码分支更新到和主分支（比如 `main`/`master`）最新状态一致，解决掉你这边的代码冲突，保证你的代码是基于最新版写的。

**再提合并申请（PR/MR）**：确认没问题后，再去提交合并请求，这样同事审核、合并代码时就不会出大麻烦，也不会把主分支的历史搞乱。

**总结：**在你自己的分支上，提前对齐主分支最新状态、解决好冲突，整理干净提交历史，再去申请合并。**更新好远程仓库，把最新版的分支状态拿过来进行对齐，当遇到同一处修改和别人起冲突，那就先解决冲突再进行合并。**

# 为什么要转C接口：

## 一、什么是 ABI？（超级简单版）

**ABI = 应用程序二进制接口**你可以把它理解成：

### **不同程序 / 库之间，在二进制层面的 “通话规则”**

#### 一句话记住：

- **API** 是给人看的函数名、参数（源代码层面）

- **ABI** 是给电脑看的二进制调用规则（编译后层面）

## 为什么 C\+\+ ABI 不稳定？

因为：

- C\+\+ 有**类、重载、虚函数、命名空间、模板**

- 每个编译器（MSVC/MinGW/GCC/Clang）对这些的**二进制编译方式不一样**

- 甚至 **VS2019 编译的 DLL，VS2022 都可能不兼容**

### 结果：

#### **C\+\+ 写的动态库，无法跨编译器、跨版本使用！**

别人用不了你的 DLL。

---

## 二、什么是 C 接口？（为什么要转？）

### **C 语言没有复杂特性，ABI 永远稳定、通用！**

不管什么编译器、什么系统：

- Windows

- Linux

- macOS

**只要是 C 接口，大家都能互相调用！**

---

## 三、C\+\+ 转 C 接口 = 做什么？

### **把 C\+\+ 的类 / 函数，包一层 C 语言格式的函数**

让动态库变成 **C 语言风格**，这样：

- 跨编译器可用

- 跨语言可用（C/C\+\+/C\#/Python/Go）

- 不崩溃、不报错

- 动态库能稳定发布

# 函数对象是什么：

在 C\+\+ 中，**函数对象（Function Object，也叫 Functor）** 是一个**重载了函数调用运算符 ****`()`**** 的类的实例**。

简单说：**它是 “长得像函数” 的对象**。

它比普通函数强大的地方在于：**它可以有状态**（成员变量），可以在调用之间保存数据。例如：

```C++
#include <iostream>

// 1. 定义一个类
class Add {
public:
    // 2. 重载函数调用运算符 ()
    int operator()(int a, int b) const {
        return a + b;
    }
};

int main() {
    Add add;      // 创建一个对象实例
    std::cout << add(1, 2); // 3. 像函数一样调用它！
    // 等价于 add.operator()(1, 2);
    return 0;
}
```

## 什么是初始化列表：

是专门用来**给类的成员变量赋值**的语法，核心作用是**初始化成员变量**。举例：

```C++
#include <iostream>
class MyClass {
private:
    // 类的成员变量
    int data; 
public:
    // 构造函数 + 初始化列表
    MyClass(int value) : data(value) {
        std::cout << "MyClass constructed: " << data << std::endl;
    }
};
```

**注意**，声明变量后初始化变量时顺序要和声明时的顺序保持一致。

## 标准范围for循环：

专门用来**遍历数组 / 容器的每一个元素。**

```C++
// C++11的范围for循环
int numbers[] = {1, 2, 3, 4, 5};
cout << "数组元素: ";
for (int num : numbers) 
{
    cout << num << " ";
}
```

### 注意：

1. 这种循环叫 **范围 for 循环（range\-based for loop）。**

2. 只能用来**遍历**，不能修改数组大小。

3. 如果想**修改数组元素**，可以用引用：

```C++
for (int& num : numbers) {
 num = num * 10; // 每个元素 ×10
}
```

## Lambda表达式：

## 为什么这个 Lambda 变量调用和普通变量不一样：

```C++
auto CreateOneParam = [&]()->ZZOneParamWidget*{ ... };
auto widget = CreateOneParam(); // 执行！
```

普通变量：直接写 `变量名` 就能用

## override和final：

# 拷贝构造函数：

**用一个已经存在的对象，去创建 / 初始化一个新的同类型对象**。

```C++
// 定义一个类
class Test {
public:
    int num;  // 成员变量

    // 普通构造函数
    Test(int n) {
        num = n;
        cout << "普通构造函数调用" << endl;
    }

    // 拷贝构造函数（重点！）
    Test(const Test& other) {
        // 用 other 对象的数据，初始化新对象
        num = other.num;
        cout << "拷贝构造函数调用" << endl;
    }
};

int main() {
    // 1. 创建一个旧对象
    Test obj1(100);

    // 2. 用 obj1 拷贝创建 obj2 —— 触发拷贝构造函数
    Test obj2 = obj1;

    // 验证复制成功
    cout << "obj2.num = " << obj2.num << endl;

    return 0;
}
```

## 总结

1. **拷贝构造函数 = 复制对象用的构造函数。**

2. 固定格式：`类名(const 类名& 其他对象)`。

3. 作用：用已有对象创建新对象。

# 设计模式：

## 单例模式：

创建一个类，把构造函数放在private里，防止进行外部实例化。在public里创建实例访问函数例如：

```C++
#include <iostream>
using namespace std;

class Singleton
{
private:
    // 1. 构造函数私有化
    // 外部无法 new Singleton()
    Singleton()
    {
        cout << "单例对象被创建了" << endl;
    }

    // 2. 类内部静态对象（全程序唯一）
    static Singleton instance;

public:
    // 3. 公共静态函数，用来获取唯一对象
    // 静态函数**不需要对象就能调用**，直接 类名::函数名()返回引用 
    // &，防止拷贝出新对象。
    static Singleton& getInstance()
    {
        return instance;
    }

    // 普通成员函数
    void show()
    {
        cout << "这是单例对象的方法" << endl;
    }
};

// 静态成员变量 类外初始化
Singleton Singleton::instance;

int main()
{
    // 两次获取，都是同一个对象！
    Singleton& s1 = Singleton::getInstance();
    Singleton& s2 = Singleton::getInstance();

    s1.show();
    s2.show();

    // 验证是不是同一个对象：打印地址
    cout << "s1地址：" << &s1 << endl;
    cout << "s2地址：" << &s2 << endl;

    return 0;
}
```

运行结果：

```C++
单例对象被创建了
这是单例对象的方法
这是单例对象的方法
s1地址：0xxxxxxxx
s2地址：0xxxxxxxx
```

### 函数前面加static是什么作用？

**1\.不属于某个对象，属于整个类**

- 不用创建对象就能调用。

**2\.不能访问普通成员变量 / 普通成员函数**

- 静态函数里没有 `this` 指针

- 只能访问：静态成员变量、静态成员函数

**3\.全局唯一的入口**

- 单例模式必须用 `static` 函数获取实例，因为你还没有对象，只能通过类名调用。

### 单例模式在机器视觉领域的应用：

在机器视觉里，单例模式主要管理这些：

1. **相机设备**（唯一硬件，不能重复打开）

2. **AI 模型 / 推理引擎**（加载昂贵，只加载一次）

3. **系统配置**（全局统一参数）

4. **日志、统计、系统状态**

5. **全局工具类、共享缓存**

共同点：

- **全局唯一**

- **不能重复创建**

- **整个软件到处都要用**

- **初始化代价大**

## 观察者模式：

### 一句话理解观察者模式

- 有一个**主题（Subject）**，比如 “天气站”

- 有一堆**观察者（Observer）**，比如 “手机、电脑、广告牌”

- 主题一变，**自动通知所有观察者**，观察者自己更新

```C++
#include <iostream>
#include <string>
#include <vector>

using namespace std;

// 观察者 基类（接口）
class Observer {
public:
    // 纯虚函数：子类必须实现这个方法，接收消息
    virtual void update(const string& msg) = 0;
    // 虚析构函数：保证子类安全释放
    virtual ~Observer() = default;
};

// 被观察者（主题）
class Subject {
private:
    // 观察者列表：存放所有监听者
    vector<Observer*> observers;

public:
    // 添加观察者
    void attach(Observer* o) {
        observers.push_back(o);
    }

    // 发布通知 → 发给所有观察者
    void notify(const string& msg) {
        for (auto o : observers) {
            o->update(msg);  // 调用每个观察者的update
        }
    }
};

// 具体观察者：手机
class PhoneObserver : public Observer {
public:
    void update(const string& msg) override {
        cout << "手机收到：" << msg << endl;
    }
};

// 具体观察者：电脑
class ComputerObserver : public Observer {
public:
    void update(const string& msg) override {
        cout << "电脑收到：" << msg << endl;
    }
};

int main() {
    Subject subject;         // 被观察者（发布消息的人）
    PhoneObserver phone;     // 观察者1
    ComputerObserver computer; // 观察者2

    subject.attach(&phone);  // 手机订阅
    subject.attach(&computer);// 电脑订阅

    subject.notify("今天是晴天"); // 发布消息1
    subject.notify("明天是阴天"); // 发布消息2

    return 0;
}
```

运行结果：

```C++
手机：今天是晴天
电脑：今天是晴天
手机：明天是阴天
电脑：明天是阴天
```

### 核心逻辑

1. **Observer** 有一个虚函数 `update()`，等着被通知

2. **Subject** 保存一个观察者列表

3. 调用 `subject.notify()` → 遍历列表，挨个调用 `observer->update()`

4. 每个观察者自己决定怎么处理消息

其中：

**纯虚函数**定规矩、统一接口，强迫所有观察者必须实现 update 方法。同时让 Observer 成为**抽象类**，不能被直接创建。因为它是纯虚函数的类，是**抽象基类**，只用来被继承，不允许实例化。

#### 什么是抽象类：

抽象类 = **不能创建对象、只能被继承的类**

只要一个类里**有至少一个纯虚函数**，它就是**抽象类**。

## 工厂设计模式：

### 一句话理解工厂模式

- 有**多种产品**（如：相机、检测算法、图形）

- 用一个**工厂**统一帮你创建对象，需要哪个就帮你new哪个

- 你不用 `new` 具体类，只告诉工厂你要什么

```C++
#include <iostream>
#include <string>

// 抽象产品（接口）
class Detector {
public:
    virtual void detect() = 0;
    virtual ~Detector() = default;
};

// 具体产品A：YOLO检测
class YoloDetector : public Detector {
public:
    void detect() override {
        std::cout << "YOLO 目标检测\n";
    }
};

// 具体产品B：传统视觉检测
class TraditionalDetector : public Detector {
public:
    void detect() override {
        std::cout << "传统视觉检测\n";
    }
};

// 工厂：负责创建检测器
class DetectorFactory {
public:
    static Detector* create(const std::string& type) {
        if (type == "yolo") return new YoloDetector();
        if (type == "traditional") return new TraditionalDetector();
        return nullptr;
    }
};

int main() {
    // 不用new具体类，只找工厂创建
    Detector* det1 = DetectorFactory::create("yolo");
    Detector* det2 = DetectorFactory::create("traditional");

    det1->detect();
    det2->detect();

    delete det1;
    delete det2;
    return 0;
}
```

运行结果：

```C++
YOLO 目标检测
传统视觉检测
```

### 核心逻辑：

- **把创建对象的逻辑封装起来**

- 主程序不用关心 `YoloDetector` 怎么构造

- 以后加新检测器，**只改工厂，不改主代码**

非常适合机器视觉里：

- 创建不同品牌相机

- 创建不同检测算法

- 创建不同模型（YOLO、RT\-DETR、分割…）

# 信号与槽：

## signal:

signals:直接默认public，不需要public和private限定。

## **Qt::QueuedConnection:**

**Qt::QueuedConnection = 排队执行**信号发出去后，**不立刻执行槽函数**，而是把槽函数放进**目标线程的事件队列**里，等目标线程忙完手头的事，**按顺序排队**再执行。

### 常用场景：

#### 1\. **跨线程通信（最最最常用！）**

你在 **子线程** 里发信号，要更新 **主线程的 UI**。✅ **必须用 QueuedConnection**

因为：**Qt 规定，子线程绝对不能直接改 UI！**用了这个连接，槽函数会自动跑到**主线程**执行，安全不崩溃。

假设：

- **主线程**：窗口、UI 界面

- **子线程**：后台耗时计算（下载、文件处理、循环运算）

你在**子线程**里发信号，槽函数是**更新 UI**。如果不用 `QueuedConnection`，用默认直接调用（`DirectConnection`）：

> 子线程直接冲过去，强行运行主线程 UI 的槽函数代码。
> 
> 

后果：**程序直接崩溃**。Qt 底层不允许，UI 控件不是线程安全的，多个线程同时碰一个界面，内存直接乱掉。

#### 2\. **不想阻塞当前代码执行**

你发信号的地方，**不想等槽函数跑完**，只想发完就继续走自己的代码。

#### 3\. **当前正在执行槽函数，避免递归卡死**

信号里又触发信号，容易嵌套卡死。用 QueuedConnection 可以让它**排队**，而不是嵌套死循环。

# 为什么**Qt 里布局、控件**必须用指针（堆 new），不能用栈对象？

## 生命周期必须长于构造函数

- 栈对象：`QPushButton btn;` 在**构造函数结束后就销毁**，界面上直接消失，布局变成野指针 → 崩溃。

- 堆指针：`QPushButton *btn=new QPushButton(this);` **生命周期由父对象（this）管理**，父窗口不销毁，按钮就一直在。

## Qt 对象树（父子内存管理）

Qt 控件靠**父对象自动释放内存**：

父窗口析构 → 自动 delete 所有子控件 → 无内存泄漏。

栈对象**无法安全加入对象树**，手动 `setParent(this)` 会导致**double free**（栈析构 \+ 父对象析构各删一次）。

## 为什么通常放 private？（封装原则）

- **public**：外部可直接修改按钮（如 `w->btn->setText("hack")`），破坏封装。

- **private**：只能通过类的成员函数访问，**内部状态可控、接口干净**，符合 C\+\+ 封装规范。

5\.总结3\.4点就是，在qt里配置include头文件路径和lib动态库导入库路径，在path环境变量里配置bin动态库\.dll文件路径。编译时 → 用 **lib，**运行时 → 用 **bin。**

# 为什么初始化函数都写在protected里面：

父类把通用的初始化逻辑写在 `protected` 函数里，比如创建控件、设置基础布局

子类可以重写（override）这个函数，先调用父类的初始化逻辑，再添加自己的扩展（比如添加新控件、修改样式、连接自定义信号槽）

这样既保证了父类初始化的完整性，又给子类提供了扩展点，实现了代码复用。

# 为什么 Qt 图像成员变量**不用指针**也能存大图？

## 核心原因：Qt 图像类自带「隐式共享」

你可以把 `QImage` 理解成一个**智能指针壳子**。

它内部结构是这样的：

```Plain Text
QImage 对象本身（很小，几十个字节）
    ↓ 内部持有一个指针
真正的图像像素数据（很大，存在堆上）
```

### 关键点：

1. **`QImage`**** 对象本身非常小**（栈上无压力）

2. **真正的像素数据永远存在堆上**

3. **Qt 自动管理内存，不用你管**

所以：

- 你写 `QImage img;`

- 它**不是把大图存在栈里**

- 而是**只存一个小句柄，数据在堆**

栈永远只占几十字节，**无论图片多大都不会栈溢出！**
